# UART 串行通信协议详解

## 概述

UART（Universal Asynchronous Receiver/Transmitter）是最常用的异步串行通信协议。无需时钟信号，收发双方通过约定波特率同步。

## 异步通信基础

UART 通过以下参数保证发送方和接收方正确解析数据：
- 双方预先约定波特率
- 每个数据帧以起始位为标志开始采样
- 接收方以 16 倍或 8 倍波特率的内部时钟对每位数进行过采样

## 帧格式

一个完整的 UART 数据帧包含：

```
[空闲] [起始位] [数据位 0..N-1] [校验位(可选)] [停止位] [空闲]
```

### 各字段说明
| 字段 | 长度 | 说明 |
|------|------|------|
| 起始位 (Start Bit) | 1 位 | 逻辑 0，标志帧开始 |
| 数据位 (Data Bits) | 5-9 位 | 通常 8 位，LSB 优先 |
| 校验位 (Parity Bit) | 0-1 位 | 可选：无校验/奇校验/偶校验 |
| 停止位 (Stop Bits) | 0.5/1/1.5/2 位 | 逻辑 1，通常 1 位 |

## 波特率计算

波特率计算公式：

```
BaudRate = f_ck / (USARTDIV × Oversampling)
```

其中：
- `f_ck`：USART 外设时钟频率
- `USARTDIV`：分频系数（整数部分 + 小数部分，存储在 BRR 寄存器）
- `Oversampling`：过采样倍数（8 或 16，通常 16）

**STM32 示例**：APB2 时钟 84 MHz，目标 115200 bps：
```
USARTDIV = 84,000,000 / (115200 × 16) = 45.5729
BRR = 0x2D9  (整数 45 = 0x2D, 小数 0.5729 ≈ 9/16 = 0x9)
实际波特率 = 84,000,000 / (16 × 45.5625) = 115207 bps
误差 = |115207 - 115200| / 115200 = 0.006%
```

## 波特率误差容限

异步通信中，发送方和接收方时钟频率不同会引入累积误差。以典型 1 起始位 + 8 数据位 + 1 停止位为例：
- 接收方在第 5 位（中间位）采样，允许的最大时钟偏差约为 ±5%
- 实际系统建议误差控制在 ±2% 以内

## 常用波特率

| 波特率 | 用途 |
|--------|------|
| 9600 | 低速调试、工业设备 |
| 19200 | 旧式设备 |
| 38400 | 中等速度 |
| 57600 | 中等速度 |
| 115200 | 最常用的高速调试速率 |
| 230400 | 高速通信 |
| 460800 | 高速通信 |
| 921600 | 极限速率，需短线和低噪声 |
| 1000000 | 特殊用途（如 ESP32 默认） |

## 流控制

### 硬件流控 (RTS/CTS)
- **RTS (Request To Send)**：输出信号，本端就绪时拉低，通知对方可以发送
- **CTS (Clear To Send)**：输入信号，对方就绪时拉低，允许本端发送
- 需要额外 2 根线，共 5 线（GND + TX + RX + RTS + CTS）
- 适用于高速、大数据量场景，防止接收缓冲区溢出

### 软件流控 (XON/XOFF)
- **XON (0x11)**：通知对方恢复发送
- **XOFF (0x13)**：通知对方暂停发送
- 无需额外硬件，但占用数据带宽
- 不适合传输二进制数据（可能与数据内容冲突）

## RS232 vs RS485 vs TTL

| 特性 | TTL UART | RS232 | RS485 |
|------|----------|-------|-------|
| 逻辑电平 | 0V=0, VCC=1 | -15~-3V=1, +3~+15V=0 | 差分信号 A/B |
| 通信距离 | < 1m | < 15m | < 1200m |
| 最大速率 | 取决于 MCU | 约 1 Mbps | 约 10 Mbps |
| 拓扑 | 点对点 | 点对点 | 多点（最多 32 节点） |
| 电平转换芯片 | 不需要 | MAX232/MAX3232 | MAX485/SP3485 |

### 电平注意事项
- **3.3V 与 5V**：3.3V TTL 的高电平 (2.4V+) 能被 5V 设备正确识别，但 5V 输出的 5V 高电平会损坏 3.3V 输入引脚。需要分压电阻或电平转换
- **RS232 ±12V**：绝对不能直接连接到 TTL 电平的 MCU 引脚，会永久损坏芯片

## 常见陷阱

1. **波特率不匹配**：最常见的通信失败原因，发送端和接收端波特率不一致
2. **TTL/RS232 电平接错**：将 RS232 的 ±12V 信号接入 MCU 的 3.3V 引脚会导致芯片损坏
3. **TX/RX 交叉**：发送端 TX 应接接收端 RX，初学时常接反
4. **共地遗漏**：TTL UART 通信必须共地（GND-GND 连接），否则电平参考不一致
5. **奇偶校验不匹配**：发送端启用了奇校验而接收端配置为无校验
6. **停止位不匹配**：1 位和 2 位停止位不匹配会导致偶尔的帧错误
7. **中断风暴**：未清中断标志导致 CPU 被 UART 中断占满

## 代码示例 (STM32 HAL)

```c
// 阻塞发送
uint8_t msg[] = "Hello UART\r\n";
HAL_UART_Transmit(&huart1, msg, sizeof(msg) - 1, 100);

// 中断接收（在回调中处理）
HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
// 在 HAL_UART_RxCpltCallback() 中处理接收到的字节

// DMA 接收（大批量数据）
#define RX_BUF_SIZE 256
uint8_t rx_buf[RX_BUF_SIZE];
HAL_UART_Receive_DMA(&huart1, rx_buf, RX_BUF_SIZE);
```
