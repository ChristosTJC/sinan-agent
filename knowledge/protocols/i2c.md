# I2C 总线协议详解

## 总线拓扑

I2C（Inter-Integrated Circuit）是一种双线制同步串行总线，由飞利浦（现 NXP）于 1982 年推出。

- **SCL (Serial Clock Line)**：时钟线，由主设备驱动
- **SDA (Serial Data Line)**：数据线，双向传输
- **开漏输出**：SCL 和 SDA 均为开漏（Open-Drain）结构，必须外接上拉电阻才能输出高电平
- **上拉电阻要求**：通常 4.7kΩ 连接到 VCC（3.3V 或 5V）

## 速度模式

| 模式 | 速率 | 方向 |
|------|------|------|
| Standard-mode (Sm) | 100 kHz | 双向 |
| Fast-mode (Fm) | 400 kHz | 双向 |
| Fast-mode Plus (Fm+) | 1 MHz | 双向 |
| High-speed mode (Hs) | 3.4 MHz | 单向（需要主设备发送主机码切换） |
| Ultra Fast-mode (UFm) | 5 MHz | 仅单向写 |

## 地址模式

- **7 位地址**：最常见的寻址模式，地址范围 0x08-0x77（0x00-0x07 和 0x78-0x7F 为保留地址）
- **10 位地址**：扩展寻址，使用 0x78-0x7B 作为前导码，可寻址更多从设备
- 总线上最多挂载设备数受总线电容（最大 400pF）和地址冲突限制

## 时序与信号

### 起始/停止条件
- **起始条件 (Start, S)**：SCL 为高电平时，SDA 从高到低的跳变
- **停止条件 (Stop, P)**：SCL 为高电平时，SDA 从低到高的跳变
- **重复起始 (Repeated Start, Sr)**：不发送停止条件的情况下再次发送起始条件

### 数据传输
- 每个字节 8 位，MSB 优先
- 每个字节后跟随 1 个应答位（ACK/NACK）
- 接收方在第 9 个 SCL 时钟脉冲时拉低 SDA 表示 ACK，保持高电平表示 NACK

### 应答机制
- **ACK（应答）**：第 9 个时钟脉冲时 SDA 被拉低
- **NACK（非应答）**：第 9 个时钟脉冲时 SDA 保持高电平
- 主设备读取最后一个字节后应发送 NACK 通知从设备停止发送

## 时钟拉伸 (Clock Stretching)

从设备可以将 SCL 拉低，使主设备进入等待状态。这在从设备需要更多时间处理数据时非常有用。并非所有主设备都支持时钟拉伸，STM32 I2C 硬件默认支持。

## 多主仲裁

I2C 支持多主设备架构。仲裁机制如下：
- 当多个主设备同时尝试控制总线时，在 SCL 为高电平时比较 SDA 电平
- 如果主设备输出高电平但检测到 SDA 为低（被其他设备拉低），则判定仲裁失败，立即释放总线
- 仲裁失败的主设备切换到从模式，等待总线空闲

## 上拉电阻计算

```
R_pullup = (Vcc - V_ol) / I_ol
```

其中：
- `Vcc`：电源电压（通常 3.3V 或 5V）
- `V_ol`：SDA/SCL 的低电平输出电压（通常 0.4V）
- `I_ol`：灌电流能力（通常 3mA）

**最小值限制**：R_pullup_min = (Vcc - 0.4) / 3mA ≈ 1kΩ（3.3V）或 1.5kΩ（5V）
**最大值限制**：由总线电容和上升时间决定，R_pullup_max = tr / (0.8473 × C_bus)

典型值：3.3V 系统使用 4.7kΩ，5V 系统使用 4.7kΩ 或 2.2kΩ。

## 常见陷阱

1. **遗漏上拉电阻**：SCL/SDA 线路没有上拉电阻，波形始终为低，通信失败
2. **总线电容过大**：导线过长或设备过多导致上升沿过缓，超出时序要求
3. **地址冲突**：两个设备使用相同 I2C 地址，需要更换地址或使用 I2C 多路复用器
4. **SDA 被拉死 (Stuck Low)**：从设备异常导致 SDA 持续拉低，可尝试发送 9 个 SCL 脉冲释放总线
5. **电源域不匹配**：3.3V 主设备与 5V 从设备直连，需使用电平转换器
6. **时钟拉伸不支持**：部分主设备（如 bit-bang 实现）不支持时钟拉伸，导致通信异常

## 调试方法

1. **逻辑分析仪**：同时抓取 SCL 和 SDA，解析地址/数据/ACK，确认波形时序
2. **I2C 扫描器**：运行 I2C 地址扫描程序，检测总线上所有从设备地址
3. **示波器**：检查上升沿斜率，判断上拉电阻是否合适
4. **逐字节调试**：先用 `HAL_I2C_IsDeviceReady()` 检测设备是否在线，再进行读写

## 代码示例 (STM32 HAL)

```c
// 检查从设备是否在线
if (HAL_I2C_IsDeviceReady(&hi2c1, 0x68 << 1, 3, 100) != HAL_OK) {
    // 设备无响应，检查地址和接线
}

// 从 MPU6050 的 WHO_AM_I 寄存器读取一字节
uint8_t who_am_i = 0;
HAL_I2C_Mem_Read(&hi2c1, 0x68 << 1, 0x75, I2C_MEMADD_SIZE_8BIT,
                  &who_am_i, 1, 100);

// 向 MPU6050 的 PWR_MGMT_1 写入唤醒命令
uint8_t data = 0x00;
HAL_I2C_Mem_Write(&hi2c1, 0x68 << 1, 0x6B, I2C_MEMADD_SIZE_8BIT,
                  &data, 1, 100);

// 批量读取 14 字节传感器数据
uint8_t buf[14];
HAL_I2C_Mem_Read(&hi2c1, 0x68 << 1, 0x3B, I2C_MEMADD_SIZE_8BIT,
                 buf, 14, 100);
```

> **注意**：HAL 库中 I2C 地址需要左移一位（`addr << 1`），因为 HAL 内部会处理读写位的设置。
